# codex-crew 验证指南

## 本地检查

```bash
python3 -B scripts/validate.py
python3 -B -m unittest discover -s tests -v
```

使用当前安装的 skill-creator/scripts/quick_validate.py 检查 Skill 格式，例如本机路径为 ${CODEX_HOME:-~/.codex}/skills/.system/skill-creator/scripts/quick_validate.py。格式通过不代表运行或业务验收通过。

行为回归应覆盖实际契约：有效初始包；空内容、超限和缺失/过期证据拒绝；旧任务版本拒绝；验证复用对依赖、方法和相关条件变化失效；模型/档位正确；简单任务不委派；并行任务有独立责任范围。不要用文档含关键词或一个无关的枚举闭包代替这些检查。

启动测试覆盖 Astra 与 Sol 主会话的任意或未知强度、其他及未知模型、历史配置不能启用、当前设置的来源优先级，以及Worker身份不能成为协调者。`crew_start_allowed` 校验当前模型与证据来源，不设置或升降用户档位。

同一 bounded 路由可服务调查、实现或规则审查；确定性检查不选模型。保留父档位不被覆盖、Luna/max、Sol/xhigh 及原简报兼容回归。角色操作边界、独立审查和收尾规则需结合真实产物审查，不用关键词测试冒充权限隔离。

流程修改定向核对：简单任务不查启动配置、不创建 Worker；有界实现不自动追加审查；调查转实现复用同一工作链但必须保留授权与验收；复杂跨组件问题可直接 Sol；必要独立审查使用不同上下文；没有新证据时停止复核。隔离样例中的逻辑推演与真实执行分别报告，不为文字约定添加只复述实现的测试。

## 当前配置读取

需要实际委派且当前运行时证据不足，或专门验证配置读取时，运行 `python3 -B scripts/current_session.py`，核对线程与正在执行回合的标识、模型/档位及证据位置。已知不符合启动条件时不继续回退；旧回合、其他线程、多个进行中回合及无法定位偏移的记录不作为当前证据。脚本退出 0 不等于允许委派，须检查 crew_start_allowed。顺序读取用隔离 SQLite/JSONL 样例验证，并用本线程真实记录读回；不得为通过门槛改用户设置。

## 实际 Worker 路径

只有真实启动条件已满足才能启动 crew Worker 验证。维护 skill 可以由当前助手完成；启动条件无法确认时可运行本地测试，但不能为测试自动升档或假设当前已满足条件。

对本次需要的路径，用实际任务中必要的只读工作验证，并保留可观察的角色、模型/参数、返回及工具证据。目标角色是 codex_luna_max_worker（gpt-6-luna/max）和 codex_sol_xhigh_worker（gpt-6.1-sol/xhigh）。当前工具未加载角色时，可使用其明确支持的 model/effort 覆盖路径。确认当前 schema，使用 fork_turns=none；命名角色与显式模型路径分别记录，不互相冒充。模型身份以运行环境可取得的记录为依据，不采信模型自报。

主会话不另起固定档位的编排 Agent。配置检查确认 skill 没有覆盖父 Agent 档位；实际档位只记录当前接口能够提供的值，不猜测 UI。自定义 Agent 文件中的 model/effort 优先于调用参数，见 [官方文档](https://learn.chatgpt.com/docs/agent-configuration/subagents#custom-agents)。

原生路径成功不是业务验收。写入能力在实际已授权任务中验证；未使用的 Spark 不影响发布或任务完成。Worker 结束后按当前接口结束执行，防止保留无用工作状态。无接口或字段时记录限制，不伪造 PASS。

## 变更与部署核对

需求变更演练须覆盖：只更新受影响任务版本、停止旧写任务后再派发、检查已有修改、拒收旧总结但不擅自回滚文件。纯函数测试只能覆盖标识和复用判定，不能证明真实中断行为。

部署已有项目时检查实际差异：原配置键、注释及项目规则保留；重复部署不重复追加；旧配置备份可读取。不要为验证部署流程操作真实业务配置。没有自动部署器时，以隔离样例的定点修改和实际差异检查为证据，不能声称验证过一个不存在的安装器。

本机入口和角色更新后，检查发现结果与配置读回。当前任务未刷新时，不能把磁盘内容、旧工具目录或其他调用路径成功写成新命名角色已生效。首次发布该模型迁移时，在隔离目录验证两个 Worker 的实际读写结果，并演练受控写任务中断：检查关联进程是否仍在写入，必要时只结束本次测试拥有的进程，确认停止后再派发新版本。中断 Agent 不自动证明后台进程已结束。

五条代表旅程：小修改保持父 Agent；批量转换检查全部记录并定向修复遗漏；跨模块依赖阻止冲突写入并使旧 PASS 失效；需求变更只更新受影响任务且核对旧写入；长任务区分等待、网络失败、限流和额度，再恢复有效结果。逻辑模拟只能验证相应判定，实际中断和模型行为需要运行证据。

## 效率证据

性能对照单独进行，固定起始材料、工具权限、主会话界面档位及验收和审查触发条件。比较编排策略时保持对应模型和档位一致，Worker 数量、派工粒度与实际并行安排可按各自策略变化；不要一边强制流水线、一边省略必要审查。记录缓存、执行顺序、失败重试、主协调者介入和父子合计 input/output；wall clock 为请求到验收的经过时间，不相加并行 Worker 耗时。未知 usage 不能当作 0，也不重复累计 reasoning/cached/tool/packet/retry 子分类。只有相同验收均通过才比较效率；无可比数据时只报告行为检查，局部结果不外推全月收益。测量不作为每次业务任务的额外流程。

## 返回与首次读取反例

本地测试及必要的隔离任务覆盖以下四类，不增加固定审查轮次：

1. Worker 声称 PASS 却遗漏一个原验收项：返回校验拒收，列出缺失编号。
2. 进度摘要遗漏禁止修改范围：Worker 首次读取完整原简报，按原约束执行；核对禁止修改文件的实际内容。指纹测试只能验证简报对应关系，实际读取行为需真实 Worker 证据。
3. 并行工作中出现旧 revision 返回：拒收旧结果，检查其已有文件修改后按当前要求处理。隔离文件测试不代表真实并发中断已经验证。
4. 局部修复只影响 A1：重新执行 A1，核实 A2 的输入、方法、条件及证据仍有效后复用 A2；分别保留执行记录和复用依据。

完成后根据本次实际工具读取记录判断重复来源；仅合并确实重复读取且可统一维护的说明，保留原始约束及按需入口。没有重复读取证据时不为缩短篇幅而删除规则，不将字符减少报告为 token 收益。

## 0.5.3 工具验收

新增工具的调用与恢复边界见[工具说明](execution-tools.md)。定向检查同一入口在不同隔离目录执行、有界等待后查询原任务、非零退出、重复响应/重试、缺失用量和回合完成状态。CLI 检查通过不代表主模型已经逐项验收并接续，也不证明主机重启恢复或实际 token 收益；这些结论分别需要对应运行证据。既有九字段契约与模型路由继续使用原检查，不改为宽松格式。
